# Melange

A Minecraft-style voxel engine written in **Odin** using **Raylib** 6.0 (vendored as `third_party:raylib`).

## Build & run

Always build from the project root via `run.sh`:

| Command              | What it does                                   |
|----------------------|------------------------------------------------|
| `./run.sh`           | Debug build to `build/melange`, then run it    |
| `./run.sh release`   | Optimized build (`-o:speed -no-bounds-check`) + run |
| `./run.sh build`     | Debug build only                               |
| `./run.sh profile`   | Release build with Spall profiling (`build/melange-profile`) + run; writes `build/trace.spall` |
| `./run.sh check`     | Type-check only (both normal and `PROFILE=true` builds) — use this after every edit |
| `./run.sh test`      | Run `odin test` on `tests/`, then `tests/prof/` with `-define:PROFILE=true` |
| `./run.sh terrain-preview [--seed N] [--out DIR]` | Render the terrain to `build/terrain-preview/{map,profile}.png` + print stats (no window) |

Args after the mode go to the game: `./run.sh debug --seed 42`. Game args: `--world NAME` (open or create the save `saves/NAME/`; see "World saves"), `--seed N` (default 1337 without `--world`, random for a new world; must match an existing world's seed), `--frames N` (quit cleanly after N frames — for repeatable profiling runs). Without `--world` the world isn't saved. Any of `--world` / `--seed` / `--frames` skips the title screen and goes straight into the game; with no args the game starts on the title screen (Play → world select).

- All builds use `-vet -strict-style`; code must pass both (no unused vars/imports, Odin's brace/indent style).
- **Raylib is vendored** in `third_party/raylib/`: Odin's raylib bindings plus the official raylib **6.0** `linux/libraylib.a`, linked statically (`-define:RAYLIB_SHARED=false`). Import it as `import rl "third_party:raylib"` — **never `vendor:raylib`**; the system Odin's copy is broken (Arch's package symlinks to a raylib 6.0 .so that pacman replaced with 6.2). If upgrading raylib, replace the bindings and `libraylib.a` together so versions match.
- The working directory at runtime is the project root, so load assets with paths like `assets/shaders/chunk.vs`.

## Layout

```
src/            package main — entry point, game loop, top-level state
src/world/      chunks, block types/registry, world storage, terrain generation
src/mesh/       chunk meshing (face culling, later greedy meshing), vertex data
src/render/     camera, shaders, texture atlas, draw calls, debug overlay
src/player/     input, movement, physics/collision against voxels, block picking
src/save/       world saves on disk (world.json + edits.bin), no raylib — testable
src/textedit/   single-line text editing + key repeat for menu text fields, no raylib — testable
src/settings/   player settings + settings.json (lenient load, clamped save), no raylib — testable
src/geom/       pure math, no raylib (frustum, AABB, voxel raycast) — testable without linking raylib
src/prof/       Spall profiling scopes (leaf; compiled out unless -define:PROFILE=true)
assets/shaders/ GLSL shaders (GLSL 330 — raylib's default desktop GL)
assets/textures/ block texture atlas and other images
tests/          odin test package(s); tests/prof/ is built separately with PROFILE=true
tools/          dev tools, each its own package (tools/terrainviz: terrain preview)
third_party/    vendored dependencies (raylib bindings + static lib); don't edit
build/          build output (gitignored)
saves/          world saves, one folder per world (gitignored)
settings.json   player settings (gitignored; written by the settings screen)
```

Each `src/` subdirectory is its own Odin package. Import them through the `melange` collection, e.g. `import "melange:world"`. Keep dependencies one-directional: `main → player, render → mesh → world`, `main → save → world`, `main → textedit`, `main → settings → save`; `geom` and `prof` are leaves any package may import. Tests don't link raylib, so code that needs tests must not live in a package that imports raylib. `world` must not import raylib rendering code (math types like `[3]f32` are fine).

## Working style

The user wants to build this **one step at a time**: for a new feature, explain the plan and tradeoffs (with a recommendation, and numbers when relevant) and wait for agreement before writing code; then implement only that step, with tests, and stop for review. Don't bundle roadmap items. Verify with tests (plus mutation checks for new tests), `./run.sh check`/`build`, a short run checking raylib's log, and offscreen renders (e.g. `./run.sh terrain-preview`) — don't capture the user's screen; ask them to check visuals. Update this file as decisions are made.

## Status & roadmap (as of 2026-11-23)

**Done:** chunk meshing with face culling; regions, streaming, frustum culling; noise terrain (plains + mountains) with a per-column height cache; texture atlas, chunk shader, fog, AO; Spall profiling; block picking, break / place, edit log; walking physics, crouching, speed FOV; world saves; title / pause / world select / create world / settings screens.

**Feature roadmap** (agreed 2026-11-23; in this order, each its own step or short series, planned and approved one at a time):
1. **Transparent blocks + water:** (a) cutout blocks (glass, leaves: alpha-test, no sorting); (b) blended water as a second mesh pass (back-to-front chunk order, no faces between water blocks); (c) a sea level in terrain gen (low plains flood into lakes/coasts); (d) swimming physics. Still water only; flowing water is a later feature.
2. **Compact vertex format** (mesh compression) via `rlgl`: packed vertices (~8 B instead of raylib's ~32+ B of floats) with room for separate sky-light and block-light attributes; drop raylib's CPU copy of each mesh. Measure where RAM goes (GPU meshes, CPU mesh copies, block pages) before and after. Done right before lighting so the format is designed once.
3. **Sky light + day/night:** per-block light (4 bits sky + 4 bits block = +4 KB/chunk), flood-fill propagation across chunk borders and incremental relighting on edits; sun brightness and sky color are shader uniforms (day/night never remeshes). Keep each chunk's initial sky light a pure computation (threads later); cross-chunk fix-ups on the main thread.
4. **Torches + player light:** torches use block-light propagation (same machinery as 3). The carried light (a toggle, no inventory yet) is a shader point light from the player's position, not propagated (re-flooding as the player moves would remesh many chunks per frame); tradeoff: it isn't occluded by walls.
5. **Caves / 3D noise:** sample 3D noise on a coarse grid (e.g. every 4 blocks) and interpolate (~64× fewer samples than per block; per-block ≈ 120 µs/chunk ≈ 4 ms/frame at 32 chunks/frame). Caves end "buried chunks have no faces": revisit cave culling (see Deferred).
6. **Worker threads for gen/meshing** — only if step 5's measurements call for it (likely).
7. **Biomes** (ocean, plains, mountains, forest, desert, …) from temperature/humidity noise, building on water and the mountain mask.
8. **World features:** trees, grass (X-shaped cutout model), rocks; biome-dependent. Features crossing chunk borders: each chunk deterministically places the features of nearby chunks that reach into it (generation stays pure).
9. **Stairs, slabs, vertical slabs:** partial-face meshing and culling, AO/light for partial blocks, sub-block collision boxes, shape-aware picking, block state (orientation / half) encoded in the u16 ID space.

**On hold (discussed, not built):** terrain tuning interface — turn the `TERRAIN_*` constants into a params struct that `tools/terrainviz` can override from the command line, later maybe a live in-game panel.

## Controls (debug build)

Starts in **walk mode**: mouse look; WASD walk; Space jump (hold to keep jumping); Shift sprint; Left Ctrl crouch (beats sprint). **F3 = debug mode**: fly through blocks (WASD, Space / Left Ctrl up / down, Shift = 5× sprint) and show the debug overlay; F3 again walks (lifted out of terrain if inside it). Left click break, right click place (both repeat every 0.2 s while held); 1 / 2 / 3 select stone / dirt / grass to place; F1 wireframe; F2 freeze frustum culling; **Esc pauses** (Resume / Settings / Save & Quit to Title; Esc again resumes); losing window focus also pauses (not in `--frames` runs). Only closing the window or the title's Quit exits (saving first with `--world`). `--frames N` quits after N frames. F1/F2 work in both modes. Mouse look ignores the first `CAPTURE_IGNORE_FRAMES` (10) frames after cursor capture (raylib reports one bogus jump on frame 1 or 2; ignoring only 2 frames turned a restored view about half the time). The overlay (debug mode only) shows FPS, position, seed, chunk/draw/cull counts, streaming queues and per-chunk gen/mesh times, the targeted block (coords, type, face) and the block selected for placing. The targeted block (within 5 blocks) gets a black wire outline; a white crosshair with a 1-px dark border marks the screen center.

## Engine design notes

- **Coordinates:** Y is up. World block coords are `[3]i32`; chunk coords are block coords floor-divided by chunk size (careful with negatives — use floor division, not `/`).
- **Chunks:** cubic, 16×16×16 (`CHUNK_SIZE :: 16`). Chunk coords are `[3]i32` (the world is chunked vertically too). Block data within a chunk is **always** a single flat, fixed-size array (`[CHUNK_SIZE*CHUNK_SIZE*CHUNK_SIZE]Block_ID`) for cache locality — no nested arrays, per-block pointers, maps, or sparse structures inside a chunk. `Block_ID :: distinct u16` (8 KB per chunk). Index `x + z*CHUNK_SIZE + y*CHUNK_SIZE*CHUNK_SIZE`. Since 16 is a power of two, block→chunk coord is `b >> 4` and local coord is `b & 15` (correct for negatives on `i32`).
- **Why 16³ (not 32³):** it's the largest power-of-two chunk whose worst case (3D checkerboard: 3·16³ = 12,288 faces × 4 = 49,152 vertices) fits raylib's `u16` mesh indices, so every chunk is one indexed `Mesh`. Also 8× cheaper remesh on edits and finer culling. Cost: ~5× more draw calls — keep them down by never drawing empty/buried chunks and by frustum culling. Target: runs well on weak hardware.
- **Regions:** chunks are stored in 8×8×8-chunk regions (`REGION_SIZE :: 8`, 128³ blocks, 4 MB reserved each) held in `World.regions: map[[3]i32]^Region` keyed by region coord (`chunk >> 3`, local `chunk & 7`, slot index `x + z*8 + y*64`). Neighbor chunks in the same region are found by index; only cross-region neighbors hit the map. `Chunk` is only its block array (exactly 8 KB = 2 pages); per-chunk metadata (`loaded`, `dirty`) lives in parallel arrays in `Region`.

### Region memory rules (src/world/region*.odin)

RAM follows writes, not the 4 MB reservation: region memory is anonymous `mmap`, zero-filled by the OS, and pages only get RAM when written.
- Allocate with `virtual.reserve_and_commit`, then `madvise(NOHUGEPAGE)` before touching it (this machine has THP=`always`; without it one write costs 2 MB — `tests/region_memory_test.odin` catches this). Never use `virtual.reserve` alone (PROT_NONE → reads segfault).
- Unload a chunk with `madvise(DONTNEED)` (guaranteed zero on next read). **Never `virtual.decommit`** — it uses `MADV_FREE`, which can resurrect stale blocks in a reused slot.
- `AIR == 0` is `#assert`ed: untouched memory reads as air. Writing air is always *correct*; skipping it only saves RAM. `world_set_block` with the current value writes nothing.
- Whether a chunk exists is decided only by `world_get_chunk` (nil = not loaded), never by its block data — unloaded slots still read as air.
- `^Chunk` / `Neighbors` are valid only for the current pass. Never keep them across frames: unloading a region's last chunk unmaps it.
- `world_create_chunk` / `world_unload_chunk` mark all 26 loaded surrounding chunks dirty (their meshes read this chunk's border for culling and AO); `world_set_block` marks its chunk plus every chunk whose 1-block border contains the block (1 on a face, 3 on an edge, 7 on a corner). Fill a newly created chunk (e.g. terrain gen via `chunk_set`) before the next mesh pass. Revisit when generation moves to threads.

- **Terrain** (`world/terrain.odin`): `height = BASE + plains + mask * mountains`, all 2D OpenSimplex2 (`core:math/noise`), each layer with its own seed offset:
  - **plains:** 5-octave fBm, scale 220, ±7 blocks → gently rolling (every plains step is 0–1 blocks; tested).
  - **mask:** 2-octave fBm at scale 900 through `smoothstep(0.25, 0.50)` → 0 on ~70% of the world, ramping to 1 in occasional mountain regions (the ramp = foothills). `terrain_mountain_mask` is public for tests/tools.
  - **mountains:** a broad "massif" fBm (scale 200) *stretched* from its actually-used range [-0.15, 0.55] to [0, 1] and raised to 1.7 (flat valley floors, pointed peaks), roughened by ridged fBm (`(1-|n|)²`, scale 90, strength 0.45), × 95 blocks. Lessons from tuning: ridged noise alone makes a maze of thin walls; raising raw fBm to a power without stretching crushes everything flat (fBm rarely nears ±1).
  - Heights clamp to `TERRAIN_MIN/MAX_HEIGHT` (1..110). All knobs are the `TERRAIN_*` constants at the top of the file (a proper tuning interface is planned for later).
  - **Surface material:** a column is **bare stone** if at/above `TERRAIN_STONE_LINE` (Y 34) or it steps ≥ `TERRAIN_CLIFF_STEP` (3) to a horizontal neighbor; otherwise grass + 3 dirt over stone. `column_heights_compute` samples an 18×18 height grid (1-column border) to judge steepness at chunk edges and must agree with the single-column `terrain_column` (tested on a plains and a mountain chunk).
  - `terrain_height`, `terrain_column`, `terrain_mountain_mask` and `generate_chunk(c, coord, seed)` are pure — keep them that way (threading later). Generation never writes air. `World.seed` comes from `--seed N` (default 1337, parsed in `src/args.odin`).
  - **Tuning workflow:** `./run.sh terrain-preview [--seed N]` (`tools/terrainviz`) renders a hill-shaded top-down map (2,560 blocks across) and a 1:1 side profile through the tallest peak to PNGs, and prints area fractions, height percentiles and step histograms. Far quicker than flying around. It uses raylib's CPU image functions, which work without a window. Current output for seed 1337: plains 69.7%, foothills 16.8%, mountains 13.5%, bare stone 5.4%; heights p50 8, p99 63, max 104.
  - **Height cache:** `Column_Heights` holds one chunk column's (cx, cz) classified 16×16 surface plus its `max_height`, computed once by the pure `column_heights_compute` (18×18 samples incl. border). `generate_chunk_from_heights(c, coord, &heights)` is what streaming uses: chunks whose bottom is above the column's `max_height` return instantly (no noise), deep chunks fill with stone, the rest read the shared columns. `generate_chunk(c, coord, seed)` is the uncached convenience (tests), identical output (tested for whole column stacks, plains and mountain). The `Streamer` owns the cache (`heights: map[[2]i32]^Column_Heights`), evicts columns outside `radius + unload_margin`, and clears it if the seed changes.

- **Streaming** (`world/streaming.odin`): `Streamer` keeps chunks loaded in a horizontal circle of `radius` chunks × `vertical` chunks above/below the camera's chunk (defaults **16** / ±8: radius = the render distance setting, 4–32; ±128 blocks vertically so the tallest peaks (Y 110) are meshed when standing on the plains). **Loading** walks `load_order`, every offset of the load shape sorted nearest-first once in `streamer_init` (`build_load_order`; ties y, z, x): a center change just resets the `load_next` cursor, and each update checks `center + offset` from the cursor, skipping loaded chunks, until `load_budget` (32) chunks are generated or `scan_budget` (8,192; 0 = unlimited) positions are checked — no per-move scan or sort. Overlay "to scan" = positions left (`stats.load_scan_left`, an upper bound on missing chunks). **Unloading** is spread over frames too: a center change snapshots the region keys (`unload_regions`, ~250) and resets `unload_next`; each update visits regions from there, skipping in O(1) any that are gone or entirely inside the keep range (`region_inside_keep`, farthest-corner test, brute-force tested), and checks the slots of at most `region_scan_budget` (32; 0 = unlimited) others, unloading out-of-range chunks within `unload_budget` and resuming mid-region (`unload_slot`) when that runs out. Regions created after the snapshot only hold in-range chunks. Overlay "regions to check" = `stats.unload_regions_left`. Chunks unload beyond `radius + unload_margin` (hysteresis, default 2). **Change the config only via `streamer_set_config`** (rebuilds `load_order` if radius/vertical changed and restarts both passes on the next update; the caller recomputes fog from `stream_meshed_distance`). Render distance changes at runtime through the settings screen (`game_set_render_distance` = `streamer_set_config` + fog), applied on Done, not while dragging (each change rebuilds `load_order`). After `streamer_update`, pass `Streamer.unloaded` to `render.renderer_forget_chunks`.
- **Neighbor rule:** a chunk is meshed only when all 6 neighbors are loaded (`world.neighbors_complete`). Otherwise its dirty flag is cleared and any mesh dropped; `world_create_chunk` re-dirties it when the missing neighbor arrives. So the outermost loaded ring (incl. the top/bottom of the vertical range) is loaded but never meshed, and no faces are ever emitted toward unloaded space. (`mesh.build_chunk_mesh` still treats `nil` neighbors as air, but the renderer never passes one.)
- **Measured performance** (this dev machine, release, single-threaded, seed 1337, 2026-11-22/23; re-measure after big changes):
  - Radius 28: vsync-bound at 240 Hz, CPU ≈ 1.45 ms/frame (`renderer_draw` ~850 µs for ≈7k chunk meshes, `collect dirty` ~258 µs every frame, `renderer_update` ~495 µs while loading); full area loads in ~5.5 s; peak RSS 661 MB (318 MB at radius 12). Chunk-border crossing worst update 0.18 ms release / 0.83 ms debug.
  - Per chunk: gen 1.9 µs avg (column heights 69 µs per column), mesh 5.4 µs avg (most empty; surface ~28 µs ≈ 98 ns/face, +AO ≈ 103 ns/face), upload ~20 µs. Debug meshing is ~16× slower than release.
  - Streaming's per-frame cost is dominated by generating up to 32 chunks (~0.35 ms release, ~2.7 ms debug): the levers are `load_budget` or worker threads.
  - Cheap wins if needed: `world_collect_dirty` scans every region slot each frame even when nothing is dirty; bitmask ("binary") meshing for surface chunks.
- **Fast paths** (keep them correct if terrain or block rules change): the streamer skips height computation for chunks above `TERRAIN_MAX_HEIGHT`; generation skips chunks above their column's `max_height` and fills chunks below `TERRAIN_ALL_STONE_BELOW` with stone — this relies on `terrain_height` clamping to `TERRAIN_MIN/MAX_HEIGHT`. `build_chunk_mesh` returns no faces immediately when the chunk and all six neighbors' touching layers are fully opaque.

## Profiling (Spall)

- `src/prof/prof.odin` wraps `core:prof/spall`: `prof.init(path)` / `prof.shutdown()` (main thread; init names it "main"), `prof.thread_init(name)` / `thread_shutdown()` for any other thread (phase 5 workers), `prof.scope("name")` (deferred: ends at block exit), `prof.begin`/`prof.end` where a block doesn't fit (`-strict-style` rejects a bare `{` block right after an `if` statement's closing brace). Scopes on a thread without a buffer are ignored.
- `ENABLED :: #config(PROFILE, false)`: off, every proc is empty, so scopes stay in hot code. Manual scopes only — not Odin's auto-instrumentation (would swamp tiny procs).
- Per-thread 1 MB buffer, written to the file when full (visible as "Spall Trace Buffer Flush") and at shutdown. Killing the process (Ctrl+C / SIGTERM) loses the unwritten tail — quit with Esc / window close / `--frames N`. Init spends 200 ms calibrating the TSC.
- Current scopes: `frame`, `EndDrawing` (swap + vsync wait + GPU sync), `player physics`, `pick block`, `streamer_update` › `rebuild queues`, `unload chunk`, `column heights`, `gen chunk`; `renderer_update` › `collect dirty`, `mesh chunk`, `upload`; `renderer_draw`; `debug overlay`. Keep names constant (the viewer aggregates by name).
- View traces at gravitymoth.com/spall/spall-web.html (drag & drop) or the native build (gravitymoth.itch.io/spall). It measures CPU only; GPU time would need GL timer queries.

- **Meshing:** Only emit faces adjacent to transparent/air blocks, including across chunk borders. Re-mesh a chunk (and affected neighbors) when a block changes. Upload with raylib `Mesh` + `UploadMesh`; free with `UnloadMesh` when chunks unload.
- **Meshes are indexed** with raylib's `u16` indices: 4 vertices + 6 indices per face. A chunk's worst case fits (see above), so one chunk = one `Mesh` per pass, never split. Don't grow `CHUNK_SIZE` past 16 without revisiting this. Currently one (opaque) mesh per chunk; water adds a second, transparent pass (roadmap 1b). Chunks with no faces get no mesh and no draw call.
- Meshing (CPU, pure: chunk + neighbor borders → vertex arrays) is separate from GPU upload (main thread only).
- **raylib owns `rl.Mesh` CPU arrays**: `UnloadMesh` frees them with raylib's `free()`, so `render.upload` copies `Mesh_Data` into `rl.MemAlloc` buffers. Never put Odin-allocated memory in an `rl.Mesh`. Don't nil `indices` after upload either (`DrawMesh` uses it to choose indexed drawing).
- `render.Renderer` keeps `map[[3]i32]rl.Mesh` (only chunks with faces), re-meshes up to `remesh_budget` dirty chunks per frame via one reused scratch `Mesh_Data`. Call `renderer_forget_chunk` when the world unloads a chunk.
- **Frustum culling:** `render.camera_frustum` builds planes from the camera's geometry (not matrices) using the framebuffer aspect and near/far from `rlgl.GetCullDistanceNear/Far` — don't hard-code near/far; the binding's constants don't match the compiled lib. Each chunk's 16³ AABB is tested before `DrawMesh`. F2 freezes the culling frustum for debugging.
- **Textures:** `assets/textures/atlas.png` is a 256×256 atlas: a 16×16 grid of tightly packed 16×16-px tiles, tile index = `row*16 + col` (0 = top-left, 255 = bottom-right = magenta "undefined"). Current tiles: 0 dirt, 1 grass side, 2 grass top, 3 stone. `world.BLOCK_TILES` maps each block's faces to tiles (`world.Tile`); unknown IDs get `TILE_UNDEFINED`.
  - **No atlas UVs on the CPU.** Each vertex carries its position *within* the tile (`Mesh_Data.texcoords`, exactly 0 or 1 → raylib `texcoords`) and the tile's (column, row) (`Mesh_Data.tiles` via `mesh.tile_coords` → raylib `texcoords2` → `vertexTexCoord2`). The fragment shader computes the exact texel `tile*16 + clamp(floor(uv*16), 0, 15)` and reads it with `texelFetch`, so every face shows exactly its full 16×16 texture and can never sample a neighboring tile. No UV inset (the old half-texel inset cropped half a texel off every edge and broke seamless tiling).
  - History: MSAA extrapolating UVs outside a face caused thin lines at block edges up close and sky-blue speckles far away / at grazing angles (confirmed with a red clear color). `centroid` + texel clamping + alpha = 1 fix all of it; keep them.
  - Point sampling via `texelFetch` (no filtering, no mipmaps). Mipmaps would need texture arrays (a per-tile mip chain); revisit if distant shimmer bothers us.
  - The renderer owns the atlas texture; it resets the material's albedo map to raylib's default texture before `UnloadMaterial` (which would otherwise unload the atlas too), then unloads the atlas once.
  - Vertex color = per-direction shade × AO brightness, multiplied with the texture in the shader.
- **Chunk shader** (`assets/shaders/chunk.vs/.fs`, GLSL 330): uses raylib's default attribute/uniform names (`vertexPosition`, `vertexTexCoord`, `vertexColor`, `mvp`, `matModel`, `texture0`) so `LoadShader`/`DrawMesh` bind them automatically. Output = atlas texel (`texelFetch`, see Textures) × vertex shade, then fog. `centroid` on the in-tile UV, `flat` on the tile, and `alpha = 1` are deliberate.
  - `renderer_init` returns `Init_Error` (`.Atlas` / `.Shader`). raylib silently falls back to its default shader when a shader file is missing or fails to compile, so the init checks `shader.id != rlgl.GetShaderIdDefault()`.
  - The material's original (default) shader is saved and restored before `UnloadMaterial`, which would otherwise unload our shader too; the Renderer unloads its shader and atlas exactly once.
- **Fog:** horizontal (xz) distance from the camera, matching the streaming circle; fades into `render.SKY_COLOR` (also the clear color). `fogEnd = world.stream_meshed_distance(cfg)` = `(radius - 1 - √2) * 16` (217 blocks at the default radius 16; 409 at 28): the distance within which every block's chunk is guaranteed meshed wherever the camera is in its chunk (brute-force tested). `fogStart = 0.55 * fogEnd`. Never set fogEnd beyond that or the world edge / chunk pop-in shows. The far clip plane is 4000, well beyond any fog end.
- **Meshing input:** `mesh.build_chunk_mesh_neighborhood(&world.Neighborhood, out)` takes the chunk and all 26 surrounding chunks (`world_get_neighborhood`, index via `neighborhood_index(offset)`). It copies opacity into an 18³ padded grid (`mesh.Padded`, chunk + 1-block border) so culling and AO read fixed offsets with no border branches. `build_chunk_mesh(chunk, &faces, out)` is a test convenience (edge/corner neighbors = air). The renderer still only requires the 6 face neighbors; a missing edge/corner chunk only brightens AO at that corner until it loads (which re-dirties this chunk).
- **Ambient occlusion** (0fps.net method): per face vertex, the two side blocks and the diagonal corner block on the face's open side give `ao = 0 if both sides solid else 3 - (s1 + s2 + corner)`; vertex brightness = `FACE_SHADE[face] * AO_BRIGHTNESS[ao]` ({0.45, 0.65, 0.82, 1.0}) in the vertex color. Each quad is split along the diagonal with the darker AO sum (flip when `ao0 + ao2 > ao1 + ao3`), else AO shows as diagonal streaks; both splits stay CCW (tested). Costs ~+25% per surface chunk (0.026 ms, ~103 ns/face).
- **Performance rules:** Avoid per-frame allocations in the hot path. Use explicit allocators; free chunk data and meshes on unload. Generation/meshing will move to worker threads (roadmap 6) — keep those functions free of global mutable state.

- **Block picking:** `geom.raycast_voxels(origin, dir, max_dist, data, is_solid)` (Amanatides–Woo voxel walk; `is_solid` is a parametric callback so `geom` stays independent of `world`) returns `Ray_Hit{block, normal, dist}`. `normal` = outward normal of the face entered, so `block + normal` is where a placed block goes; `{0,0,0}` when the ray starts inside a solid block (no placement then). Cells floor (negatives), zero-direction axes never step, exact edge/corner ties step x before y before z, `max_dist` must be finite. Tested against an exact slab-intersection reference on random rays. `player.pick_block(&w, camera)` casts from the eye along the view direction with `player.REACH :: 5.0`; unloaded chunks count as empty. ~0.5 µs/frame.
  - Crosshair: `geom.crosshair_rects(w, h, arm, thickness)` (pure, tested) gives the two bars; `render.draw_crosshair()` (`render/hud.odin`) draws both dark borders (`pixel_rect_grow` by 1) and then both white bars with `DrawRectangle`, so neither border crosses the other bar. Arm 10 px, thickness 2 (even → symmetric on even screen sizes); recomputed each frame, so it follows window resizes. Not color-inverting (would need a custom blend mode) — revisit if it ever looks wrong.
  - `render.draw_block_outline(block)`: `DrawCubeWires` at 1.002× (no z-fighting with the block's edges), drawn after the chunks inside `BeginMode3D` with depth test on (hidden edges stay hidden).

- **Block editing:** rules live in `world/edit.odin` (testable, no input): `world_is_solid` (loaded + opaque; also what picking uses), `world_break_block(w, hit)` (→ AIR; false if already gone), `world_place_block(w, hit, id, blocked)` into `geom.place_cell(hit)` = `block + normal` (refused with no face, overlapping `keep_clear` = the player's box (`geom.aabb_overlaps_cell`), or onto non-air; unloaded chunks are refused by `world_set_block`). `player.update_block_edit(&Edit_State, ...)` maps input: `geom.repeat_update` per button (fires on press, then every `EDIT_REPEAT` = 0.2 s while held, resets on release, never bursts after a long frame), keys 1–3 → `PLACEABLE`, at most one edit per frame (break wins).
  - Frame order: pick → edit → (re-pick if changed, for the outline) → stream → `renderer_update`, so an edit is visible the same frame: its ≤ 8 dirty chunks are nearest to the camera and remeshed first within the 64/frame budget. Corner edit ≈ 8 × (mesh + upload) ≈ 0.5 ms release.
  - Tested end to end: a corner placement dirties exactly 8 chunks and darkens the AO of the floor in the chunk diagonally across the corner.
  - Raycast test lesson: an origin exactly on a cell boundary belongs to the cell above (`[c, c+1)`); the random-ray test snaps a third of origins to integers to keep exercising that.

- **Edit log** (`world/edit_log.odin`, 2026-11-23): edits survive their chunk unloading (and, with `--world`, quitting: see "World saves"). `World.edits: map[chunk coord][dynamic]Block_Edit{index: u16, id}` (4 B/edit + one map entry per edited chunk; `edit_count` = blocks logged). `world_set_block` is the only runtime write path and records every real change (no-ops and unloaded chunks aren't logged; re-editing a block overwrites its entry, linear search). The streamer calls `world_apply_edits` right after generating each chunk — **including the sky fast path** that skips generation (placed blocks in the air), and **after** generation (generation would overwrite broken-to-air blocks). `world_create_chunk` already dirtied the chunk and its neighbors, so no extra dirty marking. Edits that restore the generated block are still stored (detecting that needs terrain noise; not worth it yet). Cost (release / debug): record 0.1–0.7 / 2.4 µs worst, apply 8 ns for a chunk without edits, < 0.5 / 6 µs for a fully edited chunk. Overlay shows "edits N in M chunks". With threads: generation stays pure, apply on the main thread.

- **World saves** (`src/save/save.odin`, 2026-11-23): `saves/<name>/` holds `world.json` (`World_Info`: `version` (`FORMAT_VERSION` 1), name, seed, `created` / `last_played` unix seconds, `player: Player_State{feet, yaw, pitch, flying}`; `core:encoding/json`, pretty) and `edits.bin` (the edit log: `world.edit_log_encode` / `edit_log_decode` in `world/edit_log.odin`; little-endian header `MLEDITS\0`, version u32, chunk count u32, then per chunk coord [3]i32, count u32, count × {index u16, id u16}; chunks sorted by coord so output is deterministic; 4 B/edit + 16 B/chunk). The decoder validates everything (magic, version, counts 1..4096 vs remaining length, index < 4096, no duplicate index or chunk, no trailing bytes) and on any error leaves the log empty — never half-loaded; tested with every truncation and each corruption. Unknown block IDs are kept. Names (`valid_name`): 1–32 ASCII letters, digits, space, `-`, `_`, no leading/trailing space (they're folder names). Every file is written to `<file>.tmp`, `fsync`ed, then renamed (a crash keeps the old save; stray `.tmp` ignored); `edits.bin` before `world.json`, so a `world.json` always has its `edits.bin` (missing = `Missing_Edits` error). A world that fails to load is never overwritten: the game prints why and exits. `src/session.odin` (package main) glues it to the game: `session_open` (create: random or `--seed` seed, spawn, save immediately; load: seed from the file, `--seed` mismatch = error, edits loaded before the first chunk streams, player restored, flying → debug mode), `session_save` (on closing the world: Save & Quit to Title / window close / `--frames` / streaming error; plus autosave every `AUTOSAVE_INTERVAL` 5 min via `session_tick`). Saved player = physics position (not interpolated); crouch isn't saved. JSON floats are written with 16 decimals (exact round trip at the magnitudes tested; values < ~0.25 can differ in the last bit). Cost (release): 4M edits (16 MB) save 38 ms with fsync, load 7 ms; typical saves are well under 1 ms. Tests run in `build/test-saves/<test>`. **World list:** `list_worlds(root)` = folders (not symlinks) with a valid name and a `world.json`; playable first by `last_played` desc then name, broken ones (`err` set) after by name; a missing root = empty. `delete_world(root, name)` refuses invalid names and anything that isn't a real directory (symlinks, files), then `remove_all`. `format_last_played(buf, now, then)`: just now (< 1 min, or in the future), N minutes/hours ago, yesterday, N days ago (< 30), else "on YYYY-MM-DD" (UTC). All tested incl. symlinks and path-traversal names. **New worlds** (`save/new_world.odin`): `seed_from_text` trims spaces; blank = `.Random` (caller picks `rand.uint64`); `parse_decimal_i64` (optional sign + digits, exact i64 range — **`strconv.parse_i64` doesn't detect overflow, it wraps, and accepts `_` and `0x`**, so don't use it for user input) = `.Number`; anything else = `.Text`, FNV-1a 64 of the trimmed bytes (pinned by a test so text seeds stay stable). `check_new_name(root, name)` → `Name_Problem` (Empty, Too_Long, Bad_Chars, Edge_Spaces, Exists = anything at that path, even a non-world folder) + `name_problem_text`.

- **Screens & Game lifecycle** (2026-11-23): `main.odin` runs a `Screen` switch (`Title`, `World_Select`, `Create_World`, `Playing`, `Paused`, `Settings`). `Game` (`src/game.odin`) is everything for one open world — `World`, `Streamer` (per world: its height cache depends on the seed), `Player`, `Session`, edit state, debug/F1/F2 flags, frustum, this frame's camera + target. `game_open(g, World_Request{name, seed, seed_set, create}, r)` (`create` = must be new: refuses an existing name instead of opening it) (via `session_open`; returns "" or why it failed, also printed; sets fog; `request_from_opts` for the command line), `game_update` (one frame of play incl. autosave tick; false = streaming failed), `game_draw(hud)` (no crosshair/overlay while paused), `game_close` (saves, frees, `render.renderer_clear_chunks`). The `Renderer` is app-wide (shader + atlas load once). Paused = nothing updates (physics, streaming, edits, autosave timer), the last frame's world is drawn under a dimmed menu. `game_capture_mouse` (open/resume) re-arms `CAPTURE_IGNORE_FRAMES` and blocks editing until both mouse buttons are up (so the resume click can't break a block). raylib's exit key is disabled (`SetExitKey(.KEY_NULL)`). Menus are raygui (`src/ui.odin`, immediate mode: `draw_title` / `draw_pause` return the clicked action, handled after `EndDrawing`; default style at text size 20, 300×44 buttons; vendored `libraygui.a` links fine with raylib 6.0). **The vendored `libraygui.a` is newer than its 4.0 Odin bindings** (it exports `GuiValueBoxFloat`, `GuiLoadStyleFromMemory`, …), so return conventions can differ from the binding comments: `GuiMessageBox` returns 0 ("closed") every frame without a click — don't use it. `GuiButton`, `GuiLock`, `GuiDisable` behave as documented. Probe any other raygui control's idle return value before relying on it. **World select** (`World_Select` state + `draw_world_select` in `ui.odin`): `save.list_worlds` rescans on entering and after a delete (not every frame); custom two-line rows (name; "Last played <relative>, seed N" or "Can't load: <err>" in red) in raygui's BUTTON style colors, scissor-clipped, wheel scroll (no draggable scrollbar, just an indicator). Click selects, double-click (< 0.4 s) / Enter plays, Up/Down move, Delete key or button opens our own confirm dialog (Delete / Cancel; other controls `GuiLock`ed meanwhile, and the dialog itself ignores clicks on the frame it opens), Esc backs out (or closes the confirm). The most recent playable world is preselected. Play Selected is disabled for broken worlds; a failed open shows the reason in red under the buttons. Quit to title from the pause menu goes to the title, not the list. Buttons in two rows: Play Selected | Create New World, Delete | Back. **Create world** (`Create_World` + `draw_create_world` in `ui.odin`): name and seed fields are our own `text_field` (see below), focus by click or Tab, Enter creates, Esc cancels back to the list. The name starts as `save.default_new_name` ("New World", then "New World 2", … — first free, gaps reused); its problem is shown live in red (re-checked only when the text changes) and disables Create, otherwise "Will be saved in saves/<name>". The seed line previews the result: random / "Seed N" / "Text seed -> N". Create opens the new world directly (`create = true`). **Text fields** (`text_field` in `ui.odin`, logic in `melange:textedit`): not `GuiTextBox` — the vendored raygui repeats keys per *frame* (40-frame delay, then one char per frame = 240 chars/s at 240 fps; compile-time constants in the prebuilt lib), its hovered colors are unreadable on our background, and its caret overlaps letters. `textedit.Field` = fixed 64-byte buffer + NUL, cursor on UTF-8 boundaries, `max_len`, insert (control chars refused) / backspace / delete / left / right / home / end / `field_insert_text` (paste); always NUL-terminated (tested incl. stale bytes after deleting a multi-byte char). `key_repeat`: action on press, then after `REPEAT_DELAY` 0.45 s every `REPEAT_INTERVAL` 1/30 s by elapsed time (frame-rate independent, tested at 30–1000 fps), ≤ 8 per frame, no catch-up burst. Drawn with `DrawTextEx` at glyph spacing 4 so the 2-px caret sits in the gap with 1 px clear; white box, dark text, blue 2-px border when focused; click places the caret at the nearest boundary; Ctrl+V pastes; long text scrolls to keep the caret visible; caret blinks (shown for 0.6 s of each second, reset by any edit). Debug builds wrap `context.allocator` in a `mem.Tracking_Allocator` and print leaks / bad frees at exit (raylib and region `mmap` memory aren't tracked); the temp allocator is freed every frame. Checked: 10 close/reopen cycles → no leaks, all meshes dropped, RSS flat.

- **Settings** (2026-11-23): `src/settings/settings.odin`: `Settings{version, render_distance (4–32, default 16), fov (50–110°, 70), mouse_sensitivity (0.1–3 × `player.MOUSE_SENSITIVITY`, 1), fov_effects (0–1, 1), vsync (true)}`, `DEFAULT`, `settings_clamp` (NaN → default), `settings_load(path) -> (s, warning)` (missing file = defaults, no warning; missing fields keep defaults; unknown fields ignored; out of range clamped; broken JSON, wrong types or a newer version = defaults + a warning, file left alone until the next save), `settings_save` (clamped, via `save.write_file_atomic`). File `settings.json` in the project root (gitignored). Loaded at startup **except in `--frames` runs** (defaults, so profiles stay comparable); v-sync goes into `SetConfigFlags` before the window opens. Screen `.Settings` (from the title or the pause menu, returns to `settings_from`; from the pause menu the frozen world is drawn under it): label + `GuiSlider` rows (idle return 0, value unchanged — probed) for render distance (whole chunks), FOV (whole degrees; at the max of 110 the label reads "Quake Pro!"), mouse sensitivity (5% steps), FOV effects (5% steps, "Off" at 0), a V-Sync On/Off button, Reset to defaults, Done (or Esc). - **Player & camera** (`player/player.odin`): `Player{body (feet), prev_feet, accumulator, alpha, eye_height, prev_eye_height, yaw, pitch, mode, waiting, fov_scale}` is owned by main; `camera_of(&p)` builds the `rl.Camera3D` each frame (never stored back). Look math is pure in `geom/look.odin`: yaw 0 = +X, increasing toward +Z (= turning right, right = forward × up); pitch up positive, clamped to ±`PITCH_LIMIT` (89°); `look_direction`, `look_basis(yaw)` (horizontal forward/right), `look_angles(dir)`. `update_look` (mouse, raylib's 0.172°/px) keeps yaw in [0, 360). `update_fly` reproduces raylib's CAMERA_FREE (per-key full speed, diagonals √2 faster), moving the feet directly (no interpolation). The eye is `feet + eye_height` (`EYE_HEIGHT` 1.62 standing, 1.27 crouched; see Crouch).

- **Walking physics** (pure in `geom/collide.odin` + `geom/body.odin`; input + loop in `player/walk.odin`):
  - **f64 positions** (`AABB`, `Body`): at x = 10,000 an f32 step is ~0.001 = the collision skin, which would let boxes slip into blocks (tested at x = ±1,000,000). The camera converts to f32.
  - **Numbers (Minecraft, except sprint):** box 0.6 × 1.8 × 0.6, eye 1.62; walk 4.317, sprint 5.912 b/s (user-tuned; Minecraft's is 5.612), crouch 1.295 (0.3 × walk); gravity 32 b/s², terminal fall 60 b/s; `JUMP_SPEED` 8.944 = √(2·32·1.25) → feet rise 1.25 (clears 1-block steps, not 2). Horizontal velocity approaches the target by `1 - exp(-rate·dt)`, rate 20/s on the ground (95% in 0.15 s), 2/s in the air. Wish direction is normalized (diagonals aren't faster, unlike fly mode).
  - **Integration:** vertical displacement uses the step's average velocity (exact under constant gravity), so jump height doesn't depend on the step size; semi-implicit Euler would lose ~0.07 blocks (tested).
  - **Collision:** `move_aabb` sweeps per axis, **Y then X then Z** (Minecraft's order: falling past a ledge edge hits its side rather than snapping on top; tested), each via `sweep_axis`: every cell layer between the leading face and the target is checked (no tunneling at any speed), stopping `COLLISION_SKIN` (0.001) short. Cells are half-open `[c, c+1)`; cells the box already overlaps are ignored (so a stuck box can move out). Blocked axes zero their velocity. `on_ground` = blocked while moving down (a ceiling bump isn't landing). No step-up; jumping only from the ground, held Space re-jumps on landing.
  - **Crouch** (Left Ctrl, walk mode only; `Body_Input.crouch`): crouch speed beats sprint; jumping still works. The eye moves to `CROUCH_EYE_HEIGHT` 1.27 at `EYE_HEIGHT_RATE` 3.5 b/s (0.1 s) via the pure `eye_height_step`, run in the fixed step and interpolated like the feet (`Player.eye_height` / `prev_eye_height`; `set_mode` stands up). The box stays 1.8 tall (with full blocks only, 1.5 would fit the same gaps; revisit with slabs). **Edge guard:** `move_aabb(..., keep_support = true)` — only when the Y sweep landed (blocked moving down; never mid-jump or mid-fall) — runs `edge_clamp` on X then Z after each wall sweep: the exact longest move keeping a solid cell within `SUPPORT_DEPTH` (0.5, so a 1-block drop is an edge) under the footprint by ≥ the skin, following runs of supported columns. Max overhang 0.3 − skin; sequential X-then-Z slides along edges and handles corners. A clamped axis counts as blocked (velocity zeroed). Unloaded chunks count as support. Tested incl. a random-platform property test and at x = ±1,000,000.
  - **World callback:** `world.world_blocks_movement` — opaque **or unloaded** (unlike picking's `world_is_solid`), so nobody falls into ungenerated space.
  - **Fixed 60 Hz:** `geom.fixed_steps(&accumulator, frame_dt)` → number of `PHYSICS_DT` steps + `alpha`; frame time capped at `MAX_FRAME_DT` (0.25 s → ≤ 15 steps). The eye is interpolated `prev_feet → body.position` by `alpha`; mouse look stays per frame. Different frame-time patterns give bit-identical positions (tested).
  - **Spawn & waiting:** `player_spawn(seed, x, z, ...)` stands on `terrain_height + 1` (computable before any chunk exists). Walk physics pauses (`waiting`) until the feet's chunk and the one below are loaded.
  - **Mode switch** (`set_mode`): resets velocity/accumulator; entering walk mode inside terrain lifts to the first whole-block height where the box fits (`find_free_lift`, ≤ `UNSTUCK_SEARCH` = 128).
  - **Speed FOV** (`geom/speed_fov.odin`, walk mode only): Minecraft's sprint FOV, driven by **actual horizontal speed** (not the Shift key), so it follows acceleration and narrows when a wall stops you. Target multiplier `speed_fov_target`: 1 at ≤ `WALK_SPEED`, `SPRINT_FOV_SCALE` 1.15 at ≥ `SPRINT_SPEED`, linear between. `Player.fov_scale` approaches it per frame by exact exponential (`speed_fov_step`, `SPEED_FOV_RATE` = ln 2 / 0.05 s: halves the gap every 50 ms like Minecraft's 20 Hz tick, 95% in ~0.22 s; frame-rate independent, tested). Drawn FOV = `speed_fov_apply(fov, scale, fov_effects)` = `fov · (1 + (scale − 1) · effects)` (also feeds the frustum). `set_mode` resets it to 1; fly mode never changes it; paused = frozen.
  - Cost ~0.5 µs/frame (`player physics` scope). Tested end to end on generated terrain (stand, walk + climb 4 s, end on top of a block).

- **No ECS.** World state is plain structs (`World`, `Renderer`, `Player`, grouped per open world in `Game`) owned by `main` and passed to procs. If mobs/items arrive, use a plain `[dynamic]Entity`.

## Deferred (not on the roadmap yet)

- Uniform chunks / palette compression of block data: an all-one-block chunk (e.g. solid stone) stores a single ID. All-air chunks already cost no RAM (region lazy pages). Decide after lighting adds per-block light storage and RAM is measured.
- Batching multiple chunk meshes per draw call, if draw calls become the bottleneck.
- Greedy meshing: conflicts with per-vertex AO and light (only identically lit faces can merge).
- Flowing water.
- Occlusion culling: "cave culling" (per-chunk face-to-face air connectivity from a flood fill at mesh time, then a BFS from the camera chunk through connected faces). Pays off once caves exist (roadmap 5). GPU occlusion queries / Hi-Z need raw GL via rlgl — avoid unless clearly needed.
- Vertical streaming range follows the camera (±8 chunks), so flying high enough drops low terrain. Revisit (e.g. load whole terrain-band columns) when it matters.

## Code conventions

- Odin style: `snake_case` procs/vars, `Ada_Case` types, `SCREAMING_SNAKE` constants.
- Prefer plain structs + procs over abstraction; no OOP-style vtables unless needed.
- Use `defer` for cleanup next to the allocation.
- Use `core:math/linalg` / raylib vector types; avoid hand-rolled vector math.
- Keep `main.odin` thin: init, loop, shutdown.
